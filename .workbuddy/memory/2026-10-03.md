  网络层是 `Services/GameClient.cs`（SignalR HubConnection 薄封装，事件在后台线程触发）。

  1. 登录从主窗口拆出：新增 `Views/LoginWindow` + `ViewModels/LoginViewModel`，
     `GameClient.ConnectAndJoinAsync` 作为“连接 + 登录/注册 + 加入房间”的唯一入口（含参数校验）。
     `App.xaml.cs` 负责流程：登录窗口（ShowDialog）→ 主窗口 → 退出房间回到登录窗口；
     `ShutdownMode = OnExplicitShutdown`。

     `GameActionFactory + GameCommands + ActionContext/ActionPlan`（阶段→操作按钮）。
  3. `MainWindow.xaml` 拆成 `Views/PlayerPanel`、`Views/ChatPanel`、`Views/ActionPanel` 三个 UserControl。
  4. 统一状态更新：属性 setter 内连锁 OnPropertyChanged（如 Phase → PhaseDisplay/PhaseBrush/IsWaiting/CanStartGame）；
     事件处理统一 `Xxx_OnYyy` 命名；回车发送改用 `KeyBinding`；画刷统一走 `UiBrushes` 缓存。
  5. 删除死代码：`ExpectedValue<T>`、`NonEmptyStringToVisibilityConverter`、`InverseBooleanConverter`。
- 测试同步：`ClientGUI.Tests` 的连接失败回归用例改测 `LoginViewModel`。
  新增 `--ui` 界面冒烟（STA 线程上实例化 LoginWindow/MainWindow，验证 XAML 资源能解析）。

## 该仓库的 WPF 坑（务必记住）

- 窗口/UserControl **根元素属性**（Background/Foreground）必须用 `DynamicResource`；
  解析这些属性时还看不到本元素下面声明的 `Resources`，用 StaticResource 会抛
  “无法找到名为 X 的资源”。（本次冒烟检查抓到的真 bug）
- 每个窗口/UserControl 都要自己合并主题字典
  （`pack://application:,,,/ClientGUI;component/Themes/Panels.xaml`，Panels 再合并 Palette + DarkTheme），
  不能依赖父级或 App 级资源。
- `PasswordBox.Password` 不可绑定，只能用 PasswordChanged + PropertyChanged 手动同步；
  元素上直接写 `Foreground` 会覆盖样式触发器（本地值优先级更高）。
- ActionPanel 的“空状态”不能用 DataTrigger 监听 `Actions.Count`，会无限测量递归（栈溢出）。

## 环境注意

- 本环境里 `.exe`（apphost）跑不起来（hostfxr 0x80070005），但 `dotnet <dll>` 可以运行；
  验证 .NET 程序请用 `dotnet Xxx.dll`。访问 localhost 服务需要清掉 HTTP_PROXY/HTTPS_PROXY。

## 加密算法 + 技能时机限制（第二次优化）

- 新增 `WerewolfGame/Crypto/FastPower.cs`：快速幂取模 `ModPow(base, exp, mod)`（平方-乘法，O(log e)）。
- 新增 `WerewolfGame/Crypto/RsaCrypto.cs`：基于 FastPower 的 RSA（GenerateKeyPair/Encrypt/Decrypt）。
  注意坑：`BigInteger(byte[])` 是有符号小端序，还原 RSA 参数必须用
  `new BigInteger(bytes, isUnsigned: true, isBigEndian: true)`，否则私钥指数 d 会被解析成负数。
- `AccountStore.Hash` 改为 `v2:` 前缀 + SHA256 + 快速幂混淆（固定演示 RSA 参数），旧账号（无前缀）仍可校验。
- 技能时机限制：`GameRoom` 新增 `_actingRole` 字段，`WaitNightActionAsync` 进入时设置并广播状态、
  退出时清空；`SubmitNightAction` 校验 `p.Role == _actingRole`，未轮到一律忽略。
  `GameStateDto` 新增 `ActingRole`（中文名），客户端据此在夜晚只对轮到的身份显示技能按钮/可选目标。
- 客户端 `GameViewModel` 新增 `ActingRole`/`IsMyTurn`（= Night && ActingRole==YourRole），
  `IsSelectable`/`CanSelectTargets` 夜晚分支加 `IsMyTurn` 约束（投票/猎人阶段不受影响）。
- 测试：`CryptoTests`（快速幂对照 BigInteger.ModPow、RSA 往返、账号哈希稳定性）；
  `NightTurnGating`（未轮到不放技能）；`IntegrationProbe` 夜间改按 ActingRole 顺序逐个提交。

## 网络层收拢 + 全程 TLS（第三次优化）

- 新增类库项目 `Werewolf.Client.Share`（net8.0），承载共享网络核心：
  `Dtos.cs`（PlayerDto/GameStateDto/JoinResult）、`Phases.cs`（Phases/Roles 常量+展示方法）、
  `GameClient.cs`（SignalR 封装 + `LoginResult` + TLS 证书信任）。
  `GameClient.TrustSelfSignedCertificates`（默认 true）：通过 `WithUrl(url, o =>
  o.HttpMessageHandlerFactory = ...)` 注入 HttpClientHandler，回调用
  `HttpClientHandler.DangerousAcceptAnyServerCertificateValidator` 信任自签名证书。
- 服务端 TLS：新增 `WerewolfGame/TlsCertificate.cs`（LoadOrCreate 加载/生成自签名 PFX，
  `CertificateRequest.CreateSelfSigned`）；`Program.cs` 改监听 `https://0.0.0.0:5001`，
  `ConfigureKestrel(k => k.ConfigureHttpsDefaults(https => https.ServerCertificate = cert))`。
- 双客户端同步接入共享库：GUI 删除 `Models/Dtos.cs`/`Models/Phases.cs`/`Services/GameClient.cs`，
  控制台 `Program.cs` 删除重复 DTO 与裸 HubConnectionBuilder，统一用 `GameClient`；
  所有 `ClientGUI.Models`/`ClientGUI.Services` using 改为 `Werewolf.Client.Share`。
  默认地址从 `http://localhost:5000/gamehub` 改为 `https://localhost:5001/gamehub`。
- 测试项目 `ClientGUI.Tests.csproj` 加共享库引用；`Program.cs` 的 `DefaultUrl` 改 https；
  TLS 端到端联调（`--server https://localhost:5001/gamehub`）全绿。

## 该仓库的关键坑（持续更新）

- 证书文件 `werewolf-server.pfx` 生成在**进程运行目录**（`Path.GetFullPath`），
  不要在仓库根目录跑服务端以免污染；用 `cd` 到临时目录再 `dotnet <dll>`。
- SignalR 客户端信任自签名证书：`WithUrl` 第二参 `HttpConnectionOptions.HttpMessageHandlerFactory`
  返回自定义 `HttpClientHandler`（`DangerousAcceptAnyServerCertificateValidator`）。
- 共享库是纯 net8.0（无 WPF），GUI（net8.0-windows）和控制台（net8.0）都能引用；
  类型名（Phases/Roles/GameClient/GameStateDto…）保持一致，所以移动后只需改 using，不改调用点。
