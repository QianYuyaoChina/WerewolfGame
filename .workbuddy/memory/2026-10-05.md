## v2.1.0：新身份（丘比特/警长）+ 可配置身份布局 + 房主设置窗口

用户需求三条：①新增丘比特、守卫、警长；②可配置身份布局（房主按比例选择各身份数量），开局公布给全房间；
③新增「房主设置」GUI 窗口（人数/密码/邀请码），且**邀请码在房主改密码后仍有效**。

先澄清后动手（AskUserQuestion 确认 4 点）：警长**不做竞选只加加权票**、丘比特**含殉情不含情侣独立胜利**、
布局**严格校验并拒绝开局**、**守卫已存在不做处理**（我按"规则不变但数量纳入布局"实现）。
- 勘察发现：`Role.Guard` **本来就存在**（夜晚守护 + 不能连守同一人），只是 `AssignRoles` 硬编码「n≥9 才给守卫」。

### 关键设计
- **`RoleLayout`（共享库）**：`Dictionary<string,int>`（键 = `Roles.*` 中文名）。
  `Default(n)` **逐人复刻旧内置比例**（这是"不配置时零回归"的硬保证，已用 4–12 人全量断言锁死）；
  `ValidateForGame(n)` 严格校验（总数==人数、狼≥1、狼<好人、警长≤1）。
- **平台保持游戏无关**：房主的「游戏私有配置」在平台侧只是**不透明 JSON 字符串**（`IGameContext.GameSettingsJson`），
  狼人杀自己解析成 `RoleLayout`；新增 `IGameContext.MaxPlayers`（房间实际上限，房主可调小）。
- **统一死亡结算 `ApplyDeaths`**：所有死亡（狼杀/毒杀/放逐/猎人开枪）都走它 → 情侣殉情链式触发 →
  返回全部出局者，调用方再处理「猎人开枪 / 警徽移交」。**殉情只在唯一的死亡入口做，才不会漏。**
- **警长**：身份的随机分配即初始持徽人；`HasBadge` 决定投票权重（3 vs 2，展示为 1.5 / 1 票）；
  淘汰后进入 `Phase.SheriffTransfer` 阶段由本人选人接手，超时/放弃则警徽作废。**警徽是公开信息**（所有视角的 `Tag` 都显示"警长"）。
- **邀请码改令牌制**（这是"改密码后邀请码仍有效"的正解）：`InvitePayload` 从 `Password` 换成 `InviteToken`；
  `GameRoom._inviteToken` 房间生命周期内稳定，改密码/改人数都不动它，只有房主显式「重置邀请令牌」才作废。
  `joinroom` 带令牌则跳过密码校验。客户端重连优先用内存令牌（密码可能已被改）。
- 新增 `Views/HostSettingsWindow`（标签页：房间 / 身份配置 / 邀请码）+ 主窗口菜单「游戏 → 房主设置…」；
  控制台加 `host` 菜单与 `cupid a b` 指令。

### 端到端探针抓到的真 Bug（值得记住）
`WerewolfGameInstance` **只在构造时读一次** `GameSettingsJson`，而房主是在**房间创建之后**才设置布局的
→ 自定义布局完全不生效，连"3 狼 1 民"这种非法布局都能开局。
修法：`Start()` 在**进游戏锁之前**重新读 `_ctx.GameSettingsJson`（该属性会取房间锁，必须遵守「房间锁 → 游戏锁」的锁序）。

## v2.2.1：修复「改房间最大人数会被自动刷新冲掉」

用户症状：在「房主设置 → 房间」里改最大人数，必须**抢手速**点保存，否则几秒后输入框跳回旧值。

根因：窗口里有个 3 秒轮询（为「跟随人数自动配置」实时重排身份用），
它每次都调用 `ApplySettings` —— 那是**完整回填**，会把 `MaxPlayersInput.Text`、
密码框、`AutoLayoutBox.IsChecked` 全部按服务端旧值重写 → 用户在跟轮询抢时间。

修法：拆成两条路径
- `ApplySettings`（私有，完整回填）：**只用于首次加载与保存之后**；
- `RefreshFromServerState`（public，非破坏性）：轮询用，只刷新房间信息 / 提示 / 邀请码（变了才刷）/
  人数变化引起的自动重排，**绝不触碰可编辑控件与勾选状态**。

顺带修掉同因导致的另外两个现象（用户没提但同样存在）：**刚输入的密码每 3 秒被清空**、
**取消勾选「跟随人数自动配置」后又被自动勾回**。

回归断言（`--ui`，+4 项）：模拟「已编辑未保存」后用旧的服务端状态刷一次，断言
最大人数文本框、密码框、勾选状态**均保持不变**（修复前该断言会因数字被写成 8 而失败）。

验收：编译 0/0；逻辑断言 627；界面冒烟 **56 项**；`--hostinvite` 通过。
