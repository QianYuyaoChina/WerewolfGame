### 架构
- 房间 = 平台宿主（房间号/密码/房主/玩家/聊天/邀请码/重连/回收）；玩法 = 可插拔游戏模块。
- 服务端契约 `WerewolfGame/Games/`：`IGameModule`（元数据+工厂）/`IGameInstance`/`IGameContext`/`IGameConfig`；
  `GameCatalog` + `GameDiscovery`（**反射发现**，新增游戏不改 `Program.cs`）。
- 狼人杀全部迁入 `WerewolfGame/Games/Werewolf/`；私有协议在 `Werewolf.Client.Share/Games/`。
- 协议：`GameStateDto` = 通用信封 + `JsonNode? GamePayload`；`PlayerDto.Tag/TagColor`；
  `Ops` 精简为通用 op，**其余 op 走 default 分支透传给游戏实例**（框架不认识具体游戏 op）；新增 `gamelist`。
- 客户端：GUI 宿主 + 操作面板插槽（`IGameViewModel` + `GameViewModelFactory` + `GamePanels.xaml` 模板）；
  控制台 `ConsoleGameRegistry` + `IConsoleGameModule`。

### 经验
- **设计的边界感要靠"独立第三方实现"来验证**——让 QA 自己写一个新游戏模块，比任何文档承诺都可信；
  并要求动手前后比对平台文件 hash，"零改动"才有证据。
- **破坏性协议变更必须逐条核对受影响的测试/探针**：架构设计曾误判四个端到端探针"不需改动"，
  实际它们直接读被移除的 DTO 字段，必然编译失败——**改动清单要按"谁直接引用了被改类型"来枚举，而不是按目录**。
