### 关键架构决策（实测得出，不是推断）
1. **WPF/控制台直接 P2P 到 `Sdk.Web` 的 `WerewolfGame` 可行，不用加 FrameworkReference**
   （FrameworkReference 经 P2P 传递，runtimeconfig 自动多出 Microsoft.AspNetCore.App），
   **无 Main 入口冲突**。试过抽 `Werewolf.Server.Hosting` 中间层 → 产物照样流过来，解决不了
   唯一的副作用，还牵动内嵌词库断言 → **否决**。
2. **客户端禁止 `using Microsoft.AspNetCore.*`** —— 客户端只有通用隐式 using，
   直接碰 `builder.WebHost.UseUrls` 会 CS1061。所有宿主能力走 `EmbeddedServerHost`。
3. **工作目录隔离靠切 CWD**：`WebApplication` **不会自动切** `Directory.CurrentDirectory`，
   而 `UndercoverGameInstance.LoadWordBank()` 依赖它，游戏模块又不许改 → 切 CWD 是唯一
   不给具体游戏开后门的办法。目录 `AppContext.BaseDirectory\embedded-server`，
   写探针失败回退 `%LOCALAPPDATA%\Werewolf\embedded-server`。
4. **端口：先绑定、失败再换下一个**（不先探测，避免 TOCTOU）。判最内层
   `SocketError.AddressAlreadyInUse` 才漂移。**绑定失败后 `app.Urls` 会抛 ObjectDisposedException**，
   实际端口必须从循环变量取。
5. **收尾顺序：退出房间 → 断自己的连接 → 停服务器**。断连接必须在停服务器之前，
   否则自己的长连接会让 Kestrel 优雅停止耗满 5s。总预算 8s 外层再包一层。
6. **关窗唯一入口 `App.OnExit` + `Interlocked` 幂等**；`Closing` 只做可取消的二次确认。
   退出房间复用 `GameViewModel.LeaveRoomAsync()`，新增的 `LeaveRoomForShutdownAsync()`
   只是先把 `ConfirmKeepRoom` 置成 `()=>false`。

### 坑（重要）
- **`TcpListener(IPAddress.Loopback, port)` 不能模拟端口占用** —— Windows 上它与绑
  `0.0.0.0` 的 Kestrel **不冲突**，漂移用例会假通过。必须用真实内置服务器当占用者，
  `IsPortFree` 绑 `IPAddress.Any`。
- **`MainWindow.Closed` 早于 `AppShutdown` 收尾** —— 原在 `Closed` 里注销「退出房间」委托，
  导致关窗时没人走退出房间。改为只在 `OnClosing` 且 `IsLoggedOut` 时清。
- **清理 target 必须同时挂 `Build;Publish` 且 `$(OutDir)`/`$(PublishDir)` 各删一遍** ——
  只挂 Build 的话 `dotnet publish` 出来仍脏。
- **架构文档会升版**：工程师按 v1.0 实现（Share 零改动），v1.1 才新增 E-18/E-19，
  没重读就漏了 `InviteUrlOverride` → QA 判 Engineer 打回。**动手前和交付前都要重读规范文档**。
- 交付报告要与 `git status` 核对（本次报告一度声称改了 Share，实际没改，失真）。
